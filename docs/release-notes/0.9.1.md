## 为什么要再发一版

0.9.0 只把退役名单接进「价格表剔除 + current-models billing_suspect」两处。全渠道复查时拿名单对每一层产物做差集，发现 `~/.zcode/v2/model_probe.json` 探测缓存里还躺着 9 个已退役型号（status=ok / http=200），其中 4 个是 `global:` / 裸名命名空间，连名单都没写进去。它不回流配置，但会误导排查。

**通用教训**：点名退役/黑名单机制，一要覆盖所有命名空间变体，二要接进所有消费路径（配置主链 + 探测缓存 + 统计视图 + 白名单补建）。只接主链等于没堵。详见 [PITFALLS 第 60 节](../PITFALLS.md)。
