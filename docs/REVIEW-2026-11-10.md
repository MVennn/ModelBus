## 3. 「对全局作用上了吗」—— 这是今天最值钱的一条

网关现在有 20 个别名模型、对外 93 条 id（20 别名 + 73 旧名）。同一套降级代码在各模型上的实际覆盖：

| 能力 | 需要满足的条件（代码位置） | 实际覆盖 |
|---|---|---|
| 并发对冲 / 竞速 | `race.go:306-334`：≥2 跳 + 流式 + **每跳协议都是 chat** + **每跳渠道都在 `channelPolicy` 里** + 策略里 `hedgeAfterMs>0` 或 `firstBlockMs>0` | **1 个模型**：`Gemini-AIS`。`Gemini-3.8-Flash` 只有 1 跳，被「≥2 跳」挡掉 |
| 响应头看门狗关闭 | `channelPolicy[渠道].headerTimeoutSec = -1` | **2 条渠道**：GM / HJ。WB / OC / QD / QN 仍走全局 45s |
| 沉默软冷却 | `router.go:158` 读 `channelPolicy[渠道].SilenceCooldownSeconds`，缺策略 = 0 = 不冷却 | 同上 2 条渠道。**默认模型 `DeepSeek-4.1-Flash` 走 WB→OC→OC→QW，四跳都没有策略 → 没有冷却，每来一个新请求都从第一跳重新等满 45s** |
| 提前交卷 | `router.go:601-608`：流式 chat | **全局**（这是今天唯一同时对 20 个模型生效的新行为） |
| 推理档位 | `dsh_sync` 投影到 `cordis.patch.yml` | 全部 20 个（但只影响宿主的选择器，网关不读） |

**结构性结论**：今天所有「让慢变快」的机制，都挂在一个只对 1 个模型成立的判定上（全链渠道都要有 `channelPolicy`）。剩下 19 个模型拿到的只是「全局 45s 看门狗 + 串行换跳」，其中 `DeepSeek-4.1-Flash` 四跳最坏 4 × 45s ≈ 180s，且 45s 判死会返回 502 → DSH `retryPolicy` 把 `SERVER` 当可重试 → 一次自伤等于「502 + 客户端重试 + 上游重跑」。**21:30 那次 502 事故的机制，在默认模型上原封不动地还在。**

另一个放大器：`racePolicyFor` 取的是 `Chain[0]` 的渠道策略（对冲参数、响应头窗口都跟链首走）。第二十三轮「链首 GM 常态 60s 才回 503，兜底永远排在白等之后」就是被这条规则逼出来的，最后靠**拆模型**绕过，而不是修规则。

## 4. 今天为什么这么乱：同一条链改了四轮

| 时刻 | 判定阈值 | 依据 | 结果 |
|---|---|---|---|
| 18:5x | 45s 全局 | 「总得给上游一点时间」 | 一句话 3–4.5 分钟，客户端零字节 |
| 19:4x | 12s 全局 | 实测 GM 60.241s 才回 503、HJ 直连 2.5–3.1s | 8 跳全灭，连 HJ 兜底也被切掉 |
| 20:0x | GM 12s / HJ 25s | 60KB 系统提示实测 hdr 10233ms | 兜底跳勉强活，链首仍是白等 |
| 21:30 | GM/HJ 全关（-1） | GM 判死 125 次 vs 上游真 503 仅 7 次 | 判死权交回上游，本地只留对冲 |
| 22:08 | 全局 45s + 8s 提前交卷 | 客户端不该空转 | 客户端 8s 就拿到 200 和心跳 |

四轮改的是同一个数字，说明问题不在数字：**只要「本地按时间判死」这个机制在，任何一个阈值都是在赌上游今天的排队情况。** 21:30 的结论（判死权归上游）才是对的，而 22:08 的提前交卷是它的正确补法 —— 前者让本地闭嘴，后者让客户端别急。

代价是留下了三层语义叠在一起的现状：全局 45s + 渠道 -1 + 8s 提前交卷。**同一件事（等不等、等多久、超了怎么办）在三个地方各写了一遍。**

## 5. 能整合的地方（不是重构，是去掉重复的判断）

### 5.1 超时判定：三处 → 一个策略块

现状：

- `config.UpstreamHeaderTimeoutSec`（全局 45s）
- `config.ChannelPolicy.HeaderTimeoutSec`（GM/HJ = -1）
- `config.EarlyCommitMs`（8000ms）
- 常量 `upstreamHeaderTimeout`（兜底值）
- 优先级链在 `router.go:340-359`，语义是「-1=关、0=继承、>0=秒」

整合方向：一个 `timeoutPolicy`，字段只有三个语义位 —— `wait`（等多久）、`failMode`（`upstream` 交上游 / `local` 本地判死）、`commitEarly`（提前交卷毫秒）。渠道覆盖全局，不再用「-1 / 0 / 正数」这种靠符号约定表达意图的写法。收益：**下一个人不用再记「-1 是关」**，也不会再出现「全局 12s 把 HJ 兜底一起切掉」这种连坐。

### 5.2 健康状态：三张表 → 一台 hop 状态机

现状是三套互不相通的时间记录：

| 表 | 写入口 | TTL | 语义 |
|---|---|---|---|
| `cool` | `markCool` | `softCooldownSeconds` / 429 退避 / 403 池空 90s / auth 24h | 「这一跳暂时别用」 |
| `silence` | `markSilence` | `silenceCooldownSeconds`（GM/HJ 20s） | 「这一跳刚才不说话」 |
| `hopStat`（竞速观测） | `noteRaceHop` | 未提交的 `raceFailTTL 10min` / `raceOKTTL 1h` | 「这一跳首块多快」 |

三者都在描述「这一跳现在什么状态」，却各自过期、各自判定。整合成 `hopState{status, until, firstBlockMs, seen}`，一个写入口、一个读入口（`rankedChain` 直接读它），既能去掉 `noteSerialFallback` 那种靠 WARN 猜退化的做法，也能让 `/health.race` 一段把所有跳的状态一次说清。

### 5.3 档位保活：两层 → 一层

`model_alias._inherit_efforts` 与 `dsh_sync._keep_efforts` 都在做「新算出来的路由没带档位，就沿用旧的」。两层兜底写的是同一个事实，迟早分叉（今天就是同一天分别改的）。收敛方向：**`model_alias` 只负责「档位能力」的采集与继承（它知道渠道能力表），`dsh_sync` 只做纯投影**，投影结果为空就是漂移，直接报错（现在 `_keep_efforts` 把它悄悄补上，反而掩盖了漂移）。

### 5.4 执行路径：竞速与串行两套 → 一个执行器

`raceChain` 与 `attemptChain` 现在是两条并行的实现（各自处理冷却、静默、取消、写回）。它们对「一次尝试」的语义应该一样，差别只在**调度**（串行 / 并发 / 对冲延迟）。把「打一跳」抽成一个函数，竞速只负责调度，能去掉今天在两边同时出现的三处修补（沉默冷却、`attemptCtl`、`noteSerialFallback`）。

## 6. 更优实现：按性价比排

### P0-1 per-hop 策略，别让链首决定整条链

`race.go:306-334` 用 `Chain[0]` 的策略判定整条链是否竞速、对冲等多久。改为：**每一跳用自己的 `channelPolicy`，链的节奏取「最慢那一跳」的上限**。收益是直接消掉第二十三轮那次「不得不拆模型」的动机 —— 一条 GM + HJ 混合链就能自然得到「GM 慢就并发问 HJ」，不必为每个组合手工建模型。

### P0-2 默认模型补上策略（这是当前最大的裸奔面）

`DeepSeek-4.1-Flash`（DSH 的 `agent-default-model`）走 WB → OC → OC → QW，四跳全部没有 `channelPolicy`：没有对冲、没有静默冷却、每跳本地 45s 判死。最小改动是给它所在渠道补上 `silenceCooldownSeconds` 与 `headerTimeoutSec`（哪怕先沿用 GM 的 -1），这样「慢」不会再被本地翻译成 502 + 重试。**这条不做，今天的 502 事故会在默认模型上复现一次。**

### P0-3 给提前交卷加观测

`early_sse.go` 现在完全不写日志。加三样就够：一条首次交卷的 INFO（`model= / waited= / trappedBytes=`）、`/health` 里一个 `earlyCommits` 计数、失败时流内 error 事件的事件码。没有这三样，「提前交卷到底救了多少请求」永远只能靠推理。

### P1-1 单跳链别打沉默冷却

遗留项。单跳链沉默时 `markSilence` 打的是「唯一一跳」，下个请求直接被跳过 —— 对 `Gemini-3.8-Flash` 这种单跳模型等于自锁。条件很简单：`len(chain) > 1` 才 `markSilence`。

### P1-2 配置校验：单跳渠道配 `channelPolicy` 直接报错

现在靠注释约束。`racePolicyFor` 对单跳链永远返回 false，那么给它配 `hedgeAfterMs` 就是纯噪音 —— 而且会让人误以为「这个模型有对冲」。启动时校验一遍，比再写一段文档有用。

### P1-3 对外模型 id 收口

`/v1/models` 93 条 = 20 别名 + 73 旧名。旧名是历史兼容，但对外表越长，越难回答「我到底有几个模型」。至少给 `/v1/models` 分 `canonical` / `legacy` 两段输出（现在有 `canonical_id` 字段，但混在一张表里）。

### P2 其余

- 思考守卫的模型名硬编码（`Iceman` / `iceman-contributor-free`）改成能力表驱动，避免「加了模型忘了加守卫」。
- `config.go:277` 把 `EarlyCommitMs` 的 0 归一到 8000，意味着**没法通过配置关掉提前交卷**（写 0 会被改成 8000）。要么允许 -1 关闭，要么承认这是强制行为并写进文档。
- 判死日志里的窗口值不可信：`router.go:971-972` 打的是 `s.headerTimeout(channel)`（**当前**配置），不是这次实际生效的窗口。热重载后仍在途的请求会打出 `上游 0s 内没给响应头` —— 日志 21:19:33 那条就是这么来的，排查时容易被当成「0 秒就判死」的 bug。
